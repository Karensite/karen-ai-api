# Case: مدل زبانی آموزشیِ کوچک و پایگاه دانش محلی

این مخزن شامل یک مدل واژه‌ای n-gram است که از ابتدا و فقط با چند گفت‌وگوی نمونهٔ دست‌نویس داخل `data/sample_dialogues.json` آموزش می‌بیند. هیچ وزن ازپیش‌آموزش‌دیده، مدل آماده، کلید API یا سرویس هوش مصنوعی خارجی استفاده نمی‌شود. برنامه هنگام اجرا یا دریافت پیام چیزی دانلود نمی‌کند.

این مدل **دستیار قوی یا دارای درک معنایی نیست**. فقط فراوانی و ترتیب محلی واژه‌ها در نمونه‌های کوچک را می‌آموزد؛ پاسخ‌ها ممکن است تکراری، نامربوط یا نادرست باشند. این نمونه برای آموزش مفاهیم پایه است، نه استفادهٔ واقعی یا تصمیم‌گیری مهم.

## پایگاه دانش، جدا از آموزش مدل

`data/knowledge_base.json` یک مجموعهٔ محلی از بیش از ۴۰ توضیح کوتاه و دست‌نویس در موضوعات علوم پایه، ریاضی، محیط زیست و رایانه است. متن‌ها برای این پروژه نوشته شده‌اند و دادهٔ بزرگ یا دارای حق نشر از وب وارد نشده است. هنگام دریافت پیام، برنامه ابتدا تطبیق واژگانی ساده‌ای با پرسش‌ها و کلیدواژه‌های پایگاه دانش انجام می‌دهد؛ اگر تطبیق کافی نباشد، پاسخ مدل n-gram را امتحان می‌کند. پاسخ API فیلد `source` را با مقدار `knowledge_base` یا `toy_model` مشخص می‌کند.

پایگاه دانش آموزش مدل نیست: افزودن یا ویرایش مدخل‌های آن وزن‌های مدل را تغییر نمی‌دهد. جست‌وجوی آن واژگانی است، نه جست‌وجوی معنایی؛ پرسش‌هایی با واژه‌بندی متفاوت ممکن است پیدا نشوند یا تطبیق نادرست داشته باشند. پاسخ‌های این مجموعه نیز کوتاه و آموزشی‌اند و جایگزین منبع تخصصی نیستند. «بزرگ»‌کردن مخزن با متن خودکار و بی‌منبع را انجام نداده‌ایم، چون می‌تواند اطلاعات نادرست یا محتوای دارای حق نشر تولید کند. برای گسترش واقعی، داده را با مالکیت/مجوز روشن، منبع و بازبینی انسانی اضافه کنید.

## اجرا و آموزش نخستین مدل

با Python 3.10 یا جدیدتر:

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\\Scripts\\Activate.ps1
pip install -r requirements.txt
python train.py
uvicorn main:app --host 127.0.0.1 --port 8000
```

خروجی آموزش در `artifacts/model.json` ساخته می‌شود و در Git ثبت نشده است. پایگاه دانش در `data/knowledge_base.json` نگهداری می‌شود و جداگانه آموزش داده نمی‌شود. `POST /api/chat` درخواست JSON مانند `{"message":"چرخه آب چیست؟"}` می‌پذیرد و پاسخی با `response` و `source` می‌دهد. پیام باید بین ۱ تا ۲۰۰۰ نویسه باشد. `GET /health` وضعیت بارگذاری مدل و پایگاه دانش را نشان می‌دهد. اگر مدل موجود نباشد و پرسش در پایگاه دانش پاسخ نداشته باشد، API با خطای 503 پیام عمومی می‌دهد؛ هیچ مدلی دانلود نمی‌شود.

آموزش و تولید قطعی هستند: ترتیب یکسان داده، مدل یکسان و پاسخ یکسان می‌دهد. تست‌ها با `pytest` اجرا می‌شوند و برای مدل/API هیچ شبکه یا سرویس خارجی لازم ندارند.

## افزودن داده به پایگاه دانش

هر مدخل باید این ساختار را داشته باشد؛ سؤال و پاسخ دست‌نویس باشند و کلیدواژه‌ها مرتبط و متمایز انتخاب شوند:

```json
{"question":"پرسش کوتاه؟","keywords":["واژه۱","واژه۲"],"answer":"پاسخ کوتاه و بازبینی‌شده."}
```

مجموعهٔ فعلی از فایل JSON محلی خوانده می‌شود و با متغیر `KNOWLEDGE_BASE_PATH` می‌توان مسیر فایل را تغییر داد. فایل باید در دسترس و دارای JSON معتبر باشد. برای مجموعه‌های بسیار بزرگ، این پیاده‌سازی خطی و واژگانی کافی نیست؛ باید سامانهٔ جست‌وجوی محلی مناسب، ارزیابی کیفیت و مستندسازی منبع/مجوز جداگانه طراحی شود.

## CORS و تنظیمات

برای محدودکردن CORS، متغیر محیطی `ALLOWED_ORIGINS` را با originهای دقیق و جداشده با کاما تنظیم کنید؛ اگر خالی باشد هیچ origin مرورگری مجاز نیست. نمونهٔ محلی (origin باید با میزبان/درگاه صفحهٔ وب شما تطبیق داشته باشد):

```bash
ALLOWED_ORIGINS=http://localhost:5500 uvicorn main:app --host 127.0.0.1 --port 8000
```

در Windows PowerShell پیش از اجرای uvicorn از `$env:ALLOWED_ORIGINS="http://localhost:5500"` استفاده کنید. در محیط deploy فقط origin واقعی فرانت‌اند خودتان را قرار دهید.

## تست

```bash
pytest -q
```

## استقرار آنلاین

GitHub مخزن کد است و به‌تنهایی این سرور را آنلاین اجرا نمی‌کند. برای استفادهٔ آنلاین باید این API را روی یک سرور/سرویس جداگانه deploy کنید، متغیر `ALLOWED_ORIGINS` و نشانی HTTPS را تنظیم کنید و صفحهٔ فرانت‌اند را جداگانه میزبانی کنید. نشانی زنده‌ای در کد پیش‌فرض نشده است. برای دسترسی از اینترنت، HTTPS، محدودسازی نرخ، پایش و مدیریت امن زیرساخت را نیز تنظیم کنید.
